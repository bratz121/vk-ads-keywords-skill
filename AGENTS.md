# vk-ads-keywords — семантика VK Ads до 15 000+ по Вордстату

Этот файл — рабочая методичка агента (Codex подхватывает `AGENTS.md` автоматически;
любой другой агент может следовать ему вручную; для Claude Code есть родная обёртка
`SKILL.md` — там то же самое плюс имена его браузерных инструментов). Превращает строку
вида «клуб миллионеров, Владивосток» в готовую семантику для VK Ads: фразы по категориям,
минус-слова, реальная частотность Вордстата и отчёт с доказательствами.

Ключевой приём — **весь список меряется одним OR-выражением** (`(ф1|ф2|…) -минус…`)
внутренним запросом Вордстата из залогиненной вкладки: точное объединение без двойного
счёта, сотня фраз за секунды. Второй приём — **аудит двойного смысла каждой фразы по её
реальной выдаче**: «уроки французского» — сериал, «клуб первых» — фильм и свингер-клубы,
«айти школа» — электронный дневник; такое видно только по строкам запросов.

Правила подбора, мусора и **лестница пластов добора** — `references/selection-rules.md`.
Протокол замера, таблица ошибок, чек-суммы — `references/wordstat.md`. Читай оба до шага 1.

## Когда использовать / когда нет

**Использовать:** нужна аудитория по ключевым фразам для VK Ads / myTarget под продукт или
оффер; проверить спрос в регионе; вычистить готовый список; добрать объём до цели
(по умолчанию 15 000 запросов за 30 дней ≈ ~10 000 аудитории VK).

**Не использовать:** прогноз бюджета/CPL (Вордстат — поисковый спрос, не охват VK);
семантика для Директа/SEO с операторами соответствия — тут группа всегда простой OR,
как фразы работают в VK Ads.

## Вход

Строка «тема, город» — этого достаточно, но старт начинается с **брифа: один короткий блок
вопросов** (всё в одном сообщении, не допрос; у каждого вопроса дефолт, ответ «на твоё
усмотрение» легален; пользователь сказал «сам реши» — пропусти вопросы и езжай на дефолтах):
кто аудитория оффера (предприниматели/наёмные, новички/действующие); город или вся РФ
(режим `city`/`rf`); цель по объёму (дефолт 15 000) и куда льём (бесплатник/подписка/продажа);
границы — можно ли широкие пласты и бренды конкурентов, что запрещено, какие свои
бренды/спикеры включить. Ответы фиксируй в карточке (`--offer`, `--forbid`).

Дальше тема названа коротко (бренд, персона, ссылка на лендинг) — **не расспрашивай сверх
брифа, а сам проведи ресёрч в сети**: что за оффер, что обещает, кто целевая аудитория,
какие есть похожие офферы и конкуренты (федеральные и в городе). Из ресёрча родятся
категории шага 1 и пласты шага 4. Несколько тёзок у персоны — выбери единственный массовый
B2C-оффер и зафиксируй гипотезу в карточке проекта (`--offer`).

## Конвейер (шаги строго по порядку, каждый один раз, назад не возвращаемся)

```
1    Подбор фраз по категориям (после ресёрча оффера)
2    Замер спроса (Вордстат, весь список + категории)
2.1  Чистка мусора + аудит двойного смысла КАЖДОЙ фразы
3    Хватает ли запросов? (цель 15 000+ или из брифа)
4    Добор пластами до цели (внутри шага — циклы «пласт → замер», это не возврат)
→    Итог и выгрузка
```

Машина состояния — `scripts/kw.py` (Python 3.9+, только stdlib). Она хранит проект, режет
дубли и поглощённые фразы (русский стеммер), держит порядок шагов и не даст закрыть 2.1
без аудита всех фраз. Основные команды (`KW` = `python scripts/kw.py`):

```bash
KW init kw-research/<имя> --name "…" --offer "…" --anchor "…" --region "Город" --target 15000 --mode city
KW status <проект>                # всегда говорит, какой шаг следующий
KW add <проект> --category "…"    # фразы в stdin, по одной на строку
KW js <проект> [--probes --in файл | --no-group]   # печатает ссылку и JS для замера
KW record <проект> --in <проект>/inbox.json        # записать результат (чек-сумма!)
KW audit <проект>                 # JS аудита двойного смысла (пачки по 25)
KW checked / rm --reason / minus <проект> add      # решения по аудиту
KW cleaned / expanded --note      # закрыть шаг 2.1 / зафиксировать конец добора
KW export <проект>                # выгрузка (открыта только на итоге)
```

Режимы: `city` — категории объединяются в одну аудиторию, цель по всему списку;
`rf` — каждая категория = отдельная аудитория, цель по каждой.

## Замер: два пути к Вордстату

`KW js` печатает ссылку на Вордстат (в ней регион проекта) и JS-код между строками
`---8<---`. Код вызывает тот же `POST /wordstat/api/getTable`, что и страница, кладёт
полный JSON в `<article id="kw-result">` и возвращает короткую сводку. Дальше два пути —
выбери по тому, какой у тебя доступ к браузеру:

**Путь A — у агента есть браузер с вкладкой, где пользователь залогинен в Яндекс**
(Claude Code + Claude in Chrome и аналоги): открой ссылку, выполни JS целиком без правок,
прочитай текст страницы (блок `kw-result`), сохрани JSON символ в символ в
`<проект>/inbox.json`, затем `KW record --in`.

**Путь B — браузера нет или он не залогинен (типичный Codex):** пользователь — курьер.
1. Отдай ему ссылку из `KW js` и JS-код целиком, попроси: открыть ссылку (он залогинен
   в Яндекс в своём браузере), F12 → Console → вставить код → Enter.
2. Когда код отработает (вернёт строку «rN готов: …»), попроси выполнить в той же консоли
   `copy(document.getElementById('kw-result').textContent)` — JSON окажется в буфере —
   и вставить его в чат.
3. Сохрани присланный JSON в `<проект>/inbox.json` без правок, затем `KW record --in`.

Правила обоих путей: JSON защищён контрольной суммой — опечатка при переносе будет
поймана (как найти битый блок пофрагментными хэшами — в `references/wordstat.md`);
каждый замер записывается `record` СРАЗУ, до изменений списка; **капчу и вход в Яндекс
агент не проходит никогда** — это делает пользователь сам; числа не выдумываются: нет
замера — нет числа. Аудит (`KW audit`) выполняется тем же путём A или B, только результат —
текстовый отчёт по фразам, он не записывается, по нему принимаются решения.

## Шаги коротко (детали — в references/)

1. **Подбор.** 3–5 категорий из ресёрча (категория = один вид фраз: «бизнес-обучение»,
   «авторы и книги», «свой бренд»…). Формулировки подсмотри пробами семян
   (`KW js --no-group --probes`). 15–40 фраз, минимум два значимых слова, без городских
   хвостов. Список до замера пользователю не показывать.
2. **Замер** всего списка и категорий.
3. (2.1) **Чистка.** Пройди крупнейшие запросы замера + аудит каждой фразы по её выдаче.
   Решения: чистая → `checked`; чужой смысл преобладает → `rm --reason`; примесь узкая →
   `minus add`. Сомнение — против фразы. Затем `cleaned --note`.
4. (3) Перемерь очищенный список. Цель взята → сразу итог.
5. (4) **Добор пластами** по лестнице из selection-rules.md: ядро → тематический интерес
   (книги/персоны/результат) → инструменты и повседневный интерес той же аудитории →
   события/клубы. Каждый пласт: кандидаты → пробы → аудит по строкам проб → add →
   checked → замер. Правда о масштабе: в отдельном городе ядро — сотни запросов, 15к
   почти всегда добирают широкие пласты — это ожидаемо, назови их в отчёте своими
   именами. Бренды конкурентов — только с явного согласия пользователя.
6. **Итог.** `KW export`: keywords.txt, категория-*.txt (для ставок/аудиторий), minus.txt,
   report.md. В ответе: категории с числами, фразы блоками кода, минус-слова, что вычищено
   и почему, статус цели. Недобор — честно, с числом и вариантами (география — через
   `KW fork` + один замер копии). Частоты отдельных фраз не печатать без запроса.

## Выход

Папка `kw-research/<имя>/`: `state.json` (всё состояние и журнал), `evidence/rN.json`
(сырые ответы Вордстата — каждое число доказуемо), `export/` (готовые списки и отчёт).
